# Phase 1: Baseline feature and window import

## Objective

Ensure the import pipeline can index the core coordinate and window data required for BoaT analysis without forcing a split-by-type index design.

## Scope

- keep a single feature index in v1
- attach `feature_type` as the canonical discriminator
- continue to accept existing feature-type values already generated by the importer
- ingest sequence report metadata into the sequence/feature layer
- ingest BUSCO and synteny-derived feature data
- ingest BED-based window metrics and aggregate into configured window sizes

## Key implementation points

- maintain the current `feature_type` naming scheme as the primary classification path
- treat current split-index names as compatibility values rather than requiring a new split architecture in v1
- support multiple window sizes via config, including 100 kb windows for small assemblies
- ensure the import logic remains generic enough to support additional metric classes without bespoke code paths

## Deliverables

- working import pipeline for:
  - sequence report
  - BUSCO tables
  - bed-derived window metrics
- sequence-level and window-level docs with the expected metadata attached
- feature records indexed with `feature_type` values already consistent with current naming

## Acceptance criteria

- import completes for standard configurations without index splits
- sequence features retain scaffold length and chromosome classification
- window docs can be generated at multiple configured window sizes
- no new type-split requirement is imposed on the base implementation

## Dependencies

- current import pipeline logic
- feature docs and type naming already in use
- bed config system

## Exit criteria

The project has a stable single-index, feature-type-based import pipeline that can carry all base analytical data.
